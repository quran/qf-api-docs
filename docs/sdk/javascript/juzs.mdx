# Juzs API

Purpose: Read juz metadata from the Content APIs.  
Use this when: You have a backend and need juz lists.  
Do not use this when: You only have frontend or mobile code with no backend.  
Backend required: Yes.  
Allowed runtimes: Node.js, serverless functions, workers.  
Required credentials: `client_id`, `client_secret`, Content API access.  
Minimal import: `@quranjs/api/server`.

Use `@quranjs/api/server`.

```ts
import { createServerClient } from "@quranjs/api/server";

const client = createServerClient({
  clientId: process.env.QF_CLIENT_ID!,
  clientSecret: process.env.QF_CLIENT_SECRET!,
  // New Backend/server apps hold granular Content scopes. Remove this line
  // for credentials that hold `content`.
  contentScopeMode: "granular",
});

const juzs = await client.content.v4.juzs.list();
```

The list has one record per juz, 30 in total.

The `mushaf` option (`@quranjs/api` 3.18.2 or later) selects the verse mapping set. The IndoPak mushafs, `6`, `7`, `14` and `15`, use the IndoPak set, where 13 juzs start or end at different verses. A mushaf with its own juz set, such as `19`, gets that set, with its own record `id`s. Other mushafs, and requests without `mushaf`, use the default set.

```ts
const indopakJuzs = await client.content.v4.juzs.list({ mushaf: 6 });
```

Use `juzNumber`, not a record's `id`, to refer to a juz. See [List juzs](/docs/content_apis_versioned/list-juzs) for the response schema.
